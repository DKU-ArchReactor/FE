# 시뮬레이션 API 연결 및 표시 값 검증

기준: `develop`의 `7560b2f` (PR #12 병합), 작업 브랜치 `fix/simulation-api-accuracy`.
레이아웃, 스타일, 패널 구성은 유지한다. PR 생성과 원격 배포는 수행하지 않았다.

## 수정한 동작

- `/`의 싱글 화면은 `mode: single`, `/pipeline`·`/management`는 `mode: pipeline`을 요청한다.
- 컴파일 결과의 `build_id` 또는 `simulation_token`을 보관하고 모드가 바뀌면 해당 엔진을 다시 호출한다. 이전 요청이 늦게 도착해도 현재 결과를 덮어쓰지 않는다.
- 컴파일·시뮬레이션 실패를 기존 오류 영역에 표시한다. 소스를 수정하거나 새로 컴파일하면 이전 실행 결과를 숨긴다.
- WB/MEM 기록을 정적 어셈블리 행 수에 억지로 맞추던 처리를 제거했다. 반복 실행과 분기, store, 오류도 실제 `history` 순서로 탐색한다.
- 두 모드 모두 위치 0은 `initial_state`, 위치 N은 N번째 클록이다. 마지막 기록까지 이동할 수 있다.
- CORE 응답의 `history.clock`은 0부터 시작한다. 화면에서는 실행 전 0과 구분하도록 1부터 표시하며, API 원본은 변경하지 않는다. 튜터·데이터패스·타이밍 표의 번호와 마지막 오류 안내도 같은 기준을 사용한다.
- 실행 단계 설명은 `stage_activity`, 레지스터·메모리는 같은 클록의 `global_result`를 사용한다. 메모리 이동 주소·값은 실제 MEM 처리 정보를 사용한다.
- 완료 명령어·스톨·포워딩 수는 엔진의 누적 지표를 사용한다. 같은 PC의 반복 실행을 중복 제거하지 않으며, 완료 전 CPI는 계산 불가로 표시한다.
- 코드 메모리는 `program.instructions`의 실제 PC·기계어를 사용한다. 고정 main 주소·가짜 기계어·고정 런타임 크기를 제거했다. 데이터/BSS 구분은 ELF 영역 정보를 사용하며, 구획선 숫자는 표시된 주소의 최솟값이다.
- 싱글 타이밍 표는 한 클록에 한 명령어를 표시한다. 오류·사이클 제한을 정상 실행으로 설명하지 않는다.
- 기존 develop의 빌드를 막던 미사용 라우트 import 2개와 파일 미리보기 안의 잘못 복사된 `secIdx` 참조를 제거했다.

## 검증

```sh
npm ci
npm test
npm run build
npm run test:live
```

`test:live`는 실제 운영 서버에서 익명 컴파일과 시뮬레이션을 호출한다. 토큰과 서명 URL은 출력하거나 파일에 저장하지 않는다.

- 회귀 테스트: 초기/마지막 상태, 반복 PC, 누적 지표, 응답 형식, 모드 전환 시 요청 경합, 소스 변경, 실제 코드 메모리와 타이밍 표.
- 운영 API: 반환값 42, 반복문·전역 메모리 합계 10, 콘솔 출력 42, 잘못 정렬된 메모리 접근, 무한 반복의 사이클 제한을 두 모드로 확인한다.
- 브라우저 통신: `http://localhost:5173`의 API preflight와 어셈블리 파일 CORS 응답을 확인한다.

## 남은 확인과 한계

- 로그인한 사용자의 저장 빌드 경로와 실제 브라우저 클릭·시각적 검증은 별도로 수행해야 한다. DOM 기반 회귀 테스트와 HTTP 검증은 브라우저 전체 검증을 대신하지 않는다.
- API에는 PC와 C 소스/컴파일러 어셈블리 행을 연결하는 DWARF 매핑이 없다. 텍스트가 양쪽에서 유일하게 일치하는 경우에만 실행 행을 표시한다. 중복 명령·의사 명령 등 확정할 수 없는 행은 임의로 강조하지 않는다. 정확한 모든 소스 행 추적은 별도 매핑 데이터가 필요하다.
- 전체 `npm run lint`에는 기존 develop에도 있는 오류 5개가 남아 있다: Header 1개, RegisterVisualizer 1개, SourceViewer 2개, TranslationEditor 1개. 이 네 파일은 이번 변경에서 수정하지 않았다. 이번 수정 파일의 lint 오류·경고는 없다.

## 직접 확인

```sh
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

로컬 `.env.local`의 `VITE_API_URL`은 운영 BE 주소를 사용한다.
`http://localhost:5173`에서 컴파일하고 초기 상태 → 한 단계 → 마지막 → 뒤로 이동 → 초기화 → 파이프라인 전환을 확인한다.
운영 CORS 설정상 `http://127.0.0.1:5173` 대신 `http://localhost:5173`으로 접속한다.
