# C·ASM 줄별 설명과 싱글 데이터 흐름

기존 튜터에서 선택한 C 줄에 연결된 ASM을 한 명령어씩 설명합니다. **이전 명령어 / 다음 명령어**로 같은 C 줄의 명령어를 넘깁니다. **설명 목차**와 **이전 설명 / 다음 설명**은 핵심 설명·처리 순서·항목 역할·포맷·개념을 짧은 페이지 단위로 보여줍니다. 목차와 페이지 이동은 고정하며, 작은 화면이나 확대 상태의 긴 내용만 현재 페이지 안에서 스크롤합니다. 통합보기 버튼과 별도 통합 창은 없습니다.

싱글 데이터패스의 **명령어 흐름**은 CU, 레지스터, ALU, 메모리와 다음 PC 사이의 경로를 표시합니다. **전체 상태**를 선택하면 기존 데이터패스 화면으로 돌아갑니다. 파이프라인 시각화에는 이 싱글 경로를 적용하지 않습니다.

명령어 흐름 패널은 현재 명령어·클록과 간단한 재생 조작만 남기고 그림이 나머지 공간을 채웁니다. C 설명·처리 순서 카드·값 목록·제어 신호의 별도 설명은 이 패널에 중복해서 쌓지 않습니다. 장치 내부에서 실제 값을 확인하고, 자세한 설명은 튜터에서 봅니다.

그림 전체가 스크롤 없이 패널에 맞춰 표시됩니다. 넓은 화면에서는 CPU와 메모리를 좌우로, 좁은 화면에서는 위아래로 배치합니다. CPU 내부의 레지스터·ALU 경로와 CPU–메모리 사이의 **시스템 버스**를 구분합니다. 주소 버스는 주황색, 데이터 버스는 파란색, 제어 버스는 보라색이며 데이터 버스에는 양방향을 표시합니다. CORE 로그에서 실제 버스 중재나 물리 배선 구조를 확인한 것은 아니므로, 버스 역할을 설명하는 개념도로 표시합니다.

현재 전송의 출발지·도착지·값을 그림 상단에 크게 표시합니다. 예를 들어 레지스터에서 ALU로 넘어가는 입력 A는 `11 · 0x0000000B`로 강조됩니다. 주소와 명령어 기계어는 의미 없는 부호 있는 십진수로 변환하지 않고 16진수로 표시합니다. 입력 도착·연산·레지스터 기록을 구분해 목적지 값을 순서대로 드러냅니다. 선과 이동점은 글씨보다 먼저 그리므로 글씨를 가리지 않습니다.

## 실행값 읽기

- 선택한 명령어의 PC와 현재 실행 프레임의 PC가 같을 때만 그 프레임의 실제 값을 표시합니다.
- 다른 명령어를 선택하면 의미를 먼저 보여줍니다. **이 명령어의 실행 시점으로 이동**을 눌러 관찰된 실행값을 확인합니다. 미래 클록의 값을 현재 값으로 가져오지 않습니다.
- CORE가 제공하지 않은 값은 `미제공`으로 표시합니다. 오류가 발생한 메모리 값이나 완료가 확인되지 않은 기록값은 숨깁니다.
- Store는 메모리 기록 경로를, Load는 메모리에서 목적지로 가는 경로를 표시합니다. x0 쓰기는 일반 레지스터 기록으로 그리지 않습니다.
- 싱글의 기본 1배속은 한 프레임당 9초이며 0.5배속은 18초, 1.5배속은 약 6초, 2배속은 4.5초입니다. 전체 Play의 클록 간격과 그림의 재생 시간이 같은 함수를 사용합니다. 파이프라인의 기존 재생 간격은 유지합니다.
- 전체 Pause와 그림 안의 Pause 모두 현재 이동점·전송 값·진행률을 함께 멈춥니다. 재생은 같은 위치에서 이어집니다. 그림의 이전·다음·다시 보기는 전체 클록 재생을 멈추고 현재 클록만 탐색합니다. 초기 상태와 Reset에서는 자동으로 흐름을 재생하지 않습니다.
- 전체 재생이 멈춰 있는 동안 스텝으로 클록을 바꿔도 그림은 일시정지를 유지합니다. 해당 클록의 흐름만 보고 싶으면 그림 안의 재생 버튼을 누릅니다. 클록 경계에서 Pause와 프레임 교체가 겹쳐도 애니메이션이 다시 시작되지 않도록 같은 규칙을 적용합니다.
- SVG 자체 타이머 대신 하나의 React 애니메이션 시계가 진행률과 경로상의 좌표를 계산합니다. 한 클록 안의 동작을 학습용으로 나누어 보여주며, 각 전송의 표시 시간이 실제 하드웨어 지연이나 추가 클록을 뜻하지 않습니다.

## 명령어 포맷

TUTOR가 `instruction_format`을 제공하면 R/I/S/B/U/J 비트 배치와 필드 역할을 표시합니다. 이전 TUTOR 응답에 이 필드가 없어도 기존 설명은 사용할 수 있습니다. 새 필드는 TUTOR 변경을 배포해야 운영 API에 포함됩니다.

## 검증

`npm test`, `npm run build`, `npm run test:browser`를 실행합니다. 줄별 흐름 테스트는 값·클록 일치, Store와 x0 Load, 오류, 시프트, 점프, 실제 이동 좌표, 전체/지역 Pause·Resume, 페이지 경계, 스크롤 없는 반응형 배치와 글씨 경계를 확인합니다. `?geometry=`로 실행하는 표시는 큰 값과 명령어별 배치를 검사하는 합성 UI 자료이며 CORE 실행의 정확성을 검증하는 자료와 구분합니다.

`tests/browser/fixtures/line-flow.json`은 실제 BE/CORE에서 실행한 `11 + 7` 예제의 연속된 `lw → lw → add → sw` 네 프레임과 직전 상태를 담은 회귀 자료입니다. 전체 프로그램의 실행 이력은 아닙니다. 매핑에서 중복된 목록을 덜어냈으며, 새 포맷 메타데이터는 로컬 TUTOR로 생성했습니다. 인증 토큰은 포함하지 않습니다. 정적 브라우저 검증 화면은 `tests/browser/line-flow.html`이고, 실제 컴파일·실행 확인은 `/pipeline?example=addition`에서 합니다.
