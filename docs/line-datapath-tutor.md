# C·ASM 줄별 설명과 싱글 데이터 흐름

컴파일·실행 후 튜터 헤더의 **C·ASM 통합 보기**를 누르면 선택한 C 줄, 연결된 ASM 목록, 설명과 데이터 흐름을 함께 볼 수 있습니다. 창 안에서도 다른 C 줄과 ASM을 선택할 수 있습니다. 기존 편집기와 튜터는 유지합니다.

싱글 데이터패스의 **명령어 흐름**은 CU, 레지스터, ALU, 메모리와 다음 PC 사이의 경로를 표시합니다. **전체 상태**를 선택하면 기존 데이터패스 화면으로 돌아갑니다. 파이프라인 시각화에는 이 싱글 경로를 적용하지 않습니다.

## 실행값 읽기

- 선택한 명령어의 PC와 현재 실행 프레임의 PC가 같을 때만 그 프레임의 실제 값을 표시합니다.
- 다른 명령어를 선택하면 의미를 먼저 보여줍니다. **이 명령어의 실행 시점으로 이동**을 눌러 관찰된 실행값을 확인합니다. 미래 클록의 값을 현재 값으로 가져오지 않습니다.
- CORE가 제공하지 않은 값은 `미제공`으로 표시합니다. 오류가 발생한 메모리 값이나 완료가 확인되지 않은 기록값은 숨깁니다.
- Store는 메모리 기록 경로를, Load는 메모리에서 목적지로 가는 경로를 표시합니다. x0 쓰기는 일반 레지스터 기록으로 그리지 않습니다.
- **흐름 설명 재생**은 한 명령어를 설명하는 순서입니다. CORE 클록을 진행하거나 싱글 실행을 여러 클록으로 나누지 않습니다.
- 실선은 데이터, 점선은 제어입니다. 그림은 논리적 경로이며 실제 단일 버스 회로를 재현한 것은 아닙니다.

## 명령어 포맷

TUTOR가 `instruction_format`을 제공하면 R/I/S/B/U/J 비트 배치와 필드 역할을 표시합니다. 이전 TUTOR 응답에 이 필드가 없어도 기존 설명은 사용할 수 있습니다. 새 필드는 TUTOR 변경을 배포해야 운영 API에 포함됩니다.

## 검증

`npm test`, `npm run build`, `npm run test:browser`를 실행합니다. 줄별 흐름 테스트는 값·클록 일치, Store와 x0 Load, 오류, 시프트, 점프, 모달 키보드 조작, 모바일과 기존 전체 상태 화면을 확인합니다.

`tests/browser/fixtures/line-flow.json`은 실제 BE/CORE에서 실행한 `11 + 7` 예제의 연속된 `lw → lw → add → sw` 네 프레임과 직전 상태를 담은 회귀 자료입니다. 전체 프로그램의 실행 이력은 아닙니다. 매핑에서 중복된 목록을 덜어냈으며, 새 포맷 메타데이터는 로컬 TUTOR로 생성했습니다. 인증 토큰은 포함하지 않습니다. 정적 브라우저 검증 화면은 `tests/browser/line-flow.html`이고, 실제 컴파일·실행 확인은 `/pipeline?example=addition`에서 합니다.
