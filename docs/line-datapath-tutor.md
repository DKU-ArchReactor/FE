# C·ASM 줄별 설명과 싱글 데이터 흐름

기존 튜터에서 선택한 C 줄에 연결된 ASM을 한 명령어씩 설명합니다. **이전 명령어 / 다음 명령어**로 같은 C 줄의 명령어를 넘깁니다. **설명 목차**와 **이전 설명 / 다음 설명**은 핵심 설명·처리 순서·항목 역할·포맷·개념을 짧은 페이지 단위로 보여줍니다. 목차와 페이지 이동은 고정하며, 작은 화면이나 확대 상태의 긴 내용만 현재 페이지 안에서 스크롤합니다. 통합보기 버튼과 별도 통합 창은 없습니다.

싱글 데이터패스의 **명령어 흐름**은 CU, 레지스터, ALU, 메모리와 다음 PC 사이의 경로를 표시합니다. **전체 상태**를 선택하면 기존 데이터패스 화면으로 돌아갑니다. 파이프라인 시각화에는 이 싱글 경로를 적용하지 않습니다.

명령어 흐름 패널은 현재 명령어·클록과 간단한 재생 조작만 남기고 그림이 나머지 공간을 채웁니다. C 설명·처리 순서 카드·값 목록·제어 신호의 별도 설명은 이 패널에 중복해서 쌓지 않습니다. 장치 내부와 이동점에서 실제 값을 확인하고, 자세한 설명은 튜터에서 봅니다.

## 실행값 읽기

- 선택한 명령어의 PC와 현재 실행 프레임의 PC가 같을 때만 그 프레임의 실제 값을 표시합니다.
- 다른 명령어를 선택하면 의미를 먼저 보여줍니다. **이 명령어의 실행 시점으로 이동**을 눌러 관찰된 실행값을 확인합니다. 미래 클록의 값을 현재 값으로 가져오지 않습니다.
- CORE가 제공하지 않은 값은 `미제공`으로 표시합니다. 오류가 발생한 메모리 값이나 완료가 확인되지 않은 기록값은 숨깁니다.
- Store는 메모리 기록 경로를, Load는 메모리에서 목적지로 가는 경로를 표시합니다. x0 쓰기는 일반 레지스터 기록으로 그리지 않습니다.
- 재생과 스텝에서 데이터가 선을 따라 이동하는 점과 값으로 표시됩니다. 싱글의 기본 1배속은 한 프레임당 12초이며, 0.5배속은 24초, 1.5배속은 8초, 2배속은 6초입니다. 전체 Play의 클록 간격과 그림의 재생 시간이 같은 함수를 사용하므로 흐름이 끝나기 전에 다음 클록으로 잘리지 않습니다. 파이프라인의 기존 재생 간격은 유지합니다.
- **천천히 다시 보기**는 전체 재생을 일시정지하고 같은 프레임을 12초에 걸쳐 설명합니다. 장치를 직접 선택하면 현재 클록에서 멈추고 선택한 경로만 4초 동안 보여줍니다. CORE 실행 결과나 클록 수를 바꾸지 않습니다.
- PC → 명령어 메모리 → CU·레지스터·즉치값 생성 → ALU 입력 선택 → 연산 → 필요한 메모리 접근 → 기록값 선택과 레지스터 복귀를 세로로 배치합니다. 파이프라인 버퍼를 싱글 데이터패스에 추가하지 않습니다.
- 실선은 데이터, 점선은 제어입니다. 그림은 논리적 경로이며 실제 단일 버스 회로를 재현한 것은 아닙니다.

## 명령어 포맷

TUTOR가 `instruction_format`을 제공하면 R/I/S/B/U/J 비트 배치와 필드 역할을 표시합니다. 이전 TUTOR 응답에 이 필드가 없어도 기존 설명은 사용할 수 있습니다. 새 필드는 TUTOR 변경을 배포해야 운영 API에 포함됩니다.

## 검증

`npm test`, `npm run build`, `npm run test:browser`를 실행합니다. 줄별 흐름 테스트는 값·클록 일치, Store와 x0 Load, 오류, 시프트, 점프, 실제 SVG 이동 좌표와 경로 시작 순서, 키보드 조작, 페이지 경계·모바일과 기존 전체 상태 화면을 확인합니다.

`tests/browser/fixtures/line-flow.json`은 실제 BE/CORE에서 실행한 `11 + 7` 예제의 연속된 `lw → lw → add → sw` 네 프레임과 직전 상태를 담은 회귀 자료입니다. 전체 프로그램의 실행 이력은 아닙니다. 매핑에서 중복된 목록을 덜어냈으며, 새 포맷 메타데이터는 로컬 TUTOR로 생성했습니다. 인증 토큰은 포함하지 않습니다. 정적 브라우저 검증 화면은 `tests/browser/line-flow.html`이고, 실제 컴파일·실행 확인은 `/pipeline?example=addition`에서 합니다.
