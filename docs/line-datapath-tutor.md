# 싱글 사이클 하드웨어 구조와 명령어 동작

선택한 C·ASM 줄의 명령어가 어떤 장치를 사용하고, 그 장치가 어떤 입력을 받아 무엇을 내보내는지 보여줍니다. 세로로 IF·ID·EX·MEM·WB를 나열하던 그림을 CPU·메모리 구조도로 교체했습니다. 튜터 화면·API·파이프라인 시각화는 이번 변경 대상이 아닙니다.

## 화면의 구조

- CPU 영역: PC, 명령어 해독, CU, 레지스터 파일, Imm Gen, 입력 MUX, ALU, 기록값 MUX, 다음 주소 회로.
- 메모리 영역: 명령어 메모리와 데이터 메모리를 구분하는 하버드형 교육 모델.
- 연결: 주소·데이터·제어의 역할과 내부 연결·CPU↔메모리 연결을 구분합니다.
- 기본 장치는 회색 표면과 분명한 회색 테두리로 구분합니다. 동작 중인 주소 경로는 주황색, 데이터 경로는 파란색, 제어 경로는 보라색으로 장치·배선·이동 값을 함께 강조합니다. 실제 CPU↔메모리 버스 전송일 때는 해당 버스 범례도 같은 색으로 켜집니다. 내부 회로 동작만으로 외부 버스 사용을 표시하지 않습니다. 제어선은 점선을 유지합니다. 장치 배치와 애니메이션 시간은 유지하며, 제어 값이 범례를 가리지 않도록 같은 총길이의 연결 경로 안에서 여백을 조정했습니다.
- 장치 면은 옅은 회색으로 채우고 CPU 내부 바탕과 구분합니다. 배선은 얇은 실선·점선과 파이프라인과 동일한 삼각 화살촉을 사용합니다. 글씨 정보와 CPU 테두리는 유지합니다.
- 장치와 전체 배선은 모든 명령어에서 고정됩니다. 사용하는 경로와 값, 선택·제어 상태만 달라집니다. 넓은 패널은 CPU 왼쪽·메모리 오른쪽, 좁고 긴 패널은 CPU 위·메모리 아래로 배치합니다. 패널 크기가 바뀔 때만 구성을 조절하며, 첫 화면을 그리기 전에 측정해 명령어 전환 시 배치가 흔들리지 않게 합니다.
- 각 장치에 역할과 현재 입력·결과를 표시합니다. 장치를 클릭하거나 키보드로 선택하면 그 장치에 관련된 동작으로 이동합니다.
- 상단에 현재 명령어와 PC를 표시합니다. 전체 상태 보기와 전체 연결 전환은 제거하고, 선택 명령어의 주요 연결과 현재 활성 경로를 표시합니다. 장치 위치와 배선 좌표는 명령어가 바뀌어도 유지됩니다.
- 장치 사이에 신호가 지나갈 간격을 확보하고 두 메모리 패널의 크기·행 간격을 맞춥니다. 패널 아래에 공간이 남으면 글씨 비율을 유지하면서 장치 높이와 세로 간격을 늘려 공간을 활용합니다.
- ALU·PC 가산·선택·해독 장치를 누르면 SVG 축소 비율에 영향을 받지 않는 큰 설명 창을 엽니다. 창을 열면 재생을 멈추며, 닫는다고 자동 재생하지 않습니다. 별도 보충 설명 버튼과 그림 아래 모델 설명 문구는 제거했습니다.
- CPU 외곽은 핀이 있는 칩 테두리로 구분합니다. 메모리는 주소와 현재 전송 상태 위주로 표시하고, ALU는 연산 이름·연산 기호·입력·강조된 결과를 표시합니다. 레지스터는 기록하지 않는 이유와 값 유지 여부를 표시합니다.
- 해독은 CU의 기능을 설명하기 위해 분리한 회로입니다. 배치는 실제 칩의 물리 배치를 복제한 것이 아니라 기능별 교육용 구성입니다. 해독에서 CU로는 연산 정보를, 레지스터로는 읽을 레지스터 번호를 전달하며 레지스터 값 전송과 구분합니다.
- 현재 동작 설명은 SVG 밖의 HTML 영역에 표시해 글씨가 그림과 함께 작아지지 않게 합니다. 명령어별로 주소 계산·연산 선택·레지스터 번호 선택의 의미를 설명합니다. MUX는 긴 32비트 값의 이동 상자와 내부 값이 들어갈 폭을 확보했습니다.
- 장치 외곽에는 핀과 레지스터 적층 모양을 사용합니다. 부품 이름은 `ALU`, `CU`로 표시하고 레지스터 비트 폭은 가운데 정렬합니다. 활성 장치에는 `주소 계산`, `조건 비교`, `주소 전달`처럼 수행 중인 동작을 표시합니다.
- 제공된 `sw t1, 4(s0)` 구조 스케치를 참고해 ALU의 `s0 + 4` 주소 계산과 `t1` 저장 데이터 출처를 구분합니다. 메모리로 가는 주소·데이터·쓰기 제어의 역할을 설명하며 Store의 레지스터 기록을 만들지 않습니다. 화면의 ABI 별칭은 해독 상세창에서 x 번호와 함께 확인합니다. IR은 현재 명령어를 보관해 해독에 제공하는 개념으로 설명하고, CORE에 없는 별도 IR 상태나 추가 클록을 만들지 않습니다.

## ALU와 PC 하드웨어 설명

ALU는 명령어에 따라 가산기·논리 회로·시프터·비교기를 구분합니다. 덧셈/뺄셈에서는 실제 입력과 CORE 결과를 식으로 표시하고, 실행 입력으로 계산한 학습용 전가산기 표를 8비트씩 확인할 수 있습니다. 표의 올림 입력은 더 낮은 비트의 계산을 포함합니다. 뺄셈은 B 반전과 첫 올림 입력 1로 설명합니다. 시프트는 1·2·4·8·16비트 선택 단계를 보여줍니다. 이 표는 게이트 전파 기록이 아니라 대표적인 회로 원리를 보여주는 모델입니다.

`전가산기 한 개 자세히`에서는 0~31번 비트를 선택해 A·B·올림 입력, XOR로 계산한 합, 다음 비트로 전달할 올림을 확인합니다.

기존 다음 주소 회로는 `PC 가산·선택`으로 표시합니다. 상세창에서 PC+4 가산기, 분기·점프 목적지 계산, PC 선택 MUX, PC 레지스터를 구분합니다. JAL/JALR는 일반 ALU 결과 필드를 목적지로 사용하지 않습니다. 명령어의 PC/기준 레지스터·즉치값을 주소 계산 블록에 전달하고, 관찰된 다음 PC와 PC+4 복귀 주소를 별도로 설명합니다.

해독 상세창에는 opcode·rd·rs1·rs2·funct3·funct7의 비트 위치와 역할, 형식별 즉치값 구성을 큰 글씨로 표시합니다. SYSTEM/FENCE의 고정 필드를 일반 산술 입력 레지스터나 즉치값으로 설명하지 않습니다.

## 해독과 제어

기계어의 실제 비트를 R/I/S/B/U/J 형식에 맞춰 나눕니다. opcode, funct3·funct7, rd·rs1·rs2, 즉치값 또는 shamt를 표시합니다. S/B/J의 흩어진 즉치값 비트를 조합하고 부호를 확장합니다. U형은 하위 12비트가 0인 값을 구성합니다. 시프트 크기는 funct7과 분리합니다. 기계어가 없거나 지원하는 형식으로 해독할 수 없으면 필드를 추정하지 않습니다.

해독에서 Imm Gen으로는 명령어 전체 대신 즉치값 필드를 모은 값을 전달합니다. B/J형은 Imm Gen에서 비트 순서를 재구성합니다. 별도 이동 공간을 확보하고 출발·도착 여백을 조정해 짧은 경로에서도 이동이 보이게 했습니다. ALU 자체 계산의 정지 구간은 줄이고, 메모리로 전달할 때는 계산과 주소 전송 상태를 구분합니다.

ALU→메모리는 결과 줄에서 메모리의 주소 줄로 연결합니다. 긴 주소 상자의 폭 때문에 양끝 여백이 이동 거리를 거의 소진하던 문제를 고쳤습니다. 넓은 화면과 세로 배치에서 실제 이동 거리가 남는지, 전달 중 값이 계속 보이는지 검증합니다.

읽을 레지스터 번호는 명령어의 rs1·rs2 필드에서 옵니다. CU에서 레지스터 값 자체가 만들어지는 것으로 표현하지 않습니다. CU는 연산과 RegWrite·MemRead·MemWrite 등 제어를 설명하며, 제어 값은 CORE 응답을 사용합니다.

다음 주소 회로는 PC+4 가산, 분기·점프 목적지 계산 및 PC 선택 MUX를 기능별로 묶은 모듈입니다. CU는 선택 신호를 보내고, 주소 자체는 이 회로에서 PC로 전달됩니다. 분기 비교 결과도 별도로 전달합니다. JAL/JALR의 PC+4 복귀 주소는 일반 ALU 결과와 구분합니다.

## 실행값과 재생

선택 명령어의 PC와 현재 실행 프레임이 일치할 때만 실제 실행값을 연결합니다. 다른 명령어·초기화 화면·파이프라인 프레임에서 값을 빌려오지 않습니다. 누락된 값은 `미제공`으로 표시합니다.

Store는 하위 8/16/32비트 기록값을 구분하고 레지스터 기록을 만들지 않습니다. Load의 부호/0 확장을 설명하며 x0 기록은 버립니다. 실행 오류가 있거나 완료가 확인되지 않은 기록은 성공한 것으로 표시하지 않습니다.

기존 값 이동 애니메이션과 전체/지역 Pause·Resume을 사용합니다. 캡슐 중심은 실제 표시 경로 위에 있고, MUX 입력과 출력은 같은 좌표·값으로 이어집니다. 이동 중 같은 자리의 고정 값과 겹치면 고정 값만 잠시 숨깁니다. 화면 크기에 맞춰 SVG 전체를 축소하며 내부 스크롤은 만들지 않습니다. 작은 화면에서는 글자도 작아지므로 큰 화면에서 장치 내용을 확인하는 것이 좋습니다.

이 그림은 CORE의 논리적 실행값을 교육용 하드웨어 모델에 연결한 것입니다. 실제 칩의 물리 배치나 메모리가 칩 밖에 있다는 구현 사실을 증명하는 그림은 아닙니다. 해독은 CU와 기능적으로 구분해 그렸으며, ALU 블록에는 입력 선택과 비교 기능이 포함됩니다. 여러 실제 주소 계산 요소를 다음 주소 모듈로 묶었습니다. 캐시·버스 중재·전기 신호·실제 전파 시간은 재현하지 않습니다. 애니메이션 구간은 한 클록 내부를 풀어 보여주는 설명 순서이며 추가 CPU 클록을 뜻하지 않습니다.

## 검증과 로컬 확인

명령어의 설명 재생이 끝나면 이동 값·활성 화살표·출발/도착 강조를 끄고 실행 결과를 유지합니다. 실행 완료가 확인된 명령어는 실행한 PC와 다음 PC를 함께 표시하며 PC 장치는 갱신된 다음 주소를 보여줍니다. 실행하지 않은 선택 명령어는 설명 재생 완료로 구분합니다. 전체 실행 결과의 마지막 프레임에서 서버의 `execution_status`가 제공된 경우에만 프로그램 완료·클록 제한·실행 오류를 표시합니다.

마지막 클록 재생 중에도 전역 일시정지와 이어보기가 같은 클록에 머뭅니다. 자연스럽게 끝나면 마지막 상태에 정지하며, 사용자가 완료 후 재생을 누르면 처음부터 다시 재생합니다. 명령어 하나의 복귀·점프와 프로그램 전체 종료를 혼동하지 않습니다.

배속을 바꿀 때 명령어 화면을 다시 생성하지 않고 현재 진행 비율을 유지한 채 애니메이션 시간과 다음 클록까지 남은 시간을 함께 조정합니다. 수동 시점 이동은 같은 클록을 다시 선택한 경우에도 새 재생으로 구분해 이전 완료 상태를 재사용하지 않습니다.

싱글 모드에서 실행 이력이 있는 ASM 줄을 클릭하면 그 PC의 실행 클록으로 함께 이동합니다. 반복 실행되는 PC는 현재 또는 이후의 첫 이력을 사용하고 이후 이력이 없으면 첫 실행으로 이동합니다. 실행 이력이 없는 줄은 설명만 선택하며 클록을 추정하지 않습니다. Play는 선택 시점 이후의 실행 이력을 계속 재생하므로 종료 지점은 ASM 줄 번호의 마지막과 다를 수 있습니다. 버스 범례는 영어 이름·확대된 글씨·굵은 선으로 구분합니다.

`npm test`, `npm run build`, `npm run test:browser`로 검증합니다. 비트 해독은 독립적인 명령어 인코딩으로 검사합니다. 브라우저 검사는 고정 장치/배선, CPU·메모리 경계, 값과 장치 역할, 메모리 읽기/쓰기, 글씨 경계, 실제 이동 좌표·값, MUX 연속성, 전체/지역 Pause·Resume을 확인합니다.

`tests/browser/fixtures/line-flow.json`은 실제 BE/CORE에서 실행한 `11 + 7` 예제의 연속 `lw → lw → add → sw` 프레임과 직전 상태를 담은 회귀 자료입니다. `?geometry=` 화면은 큰 값과 명령어별 표시를 검증하는 합성 자료이며 CORE 정확성의 증거와 구분합니다. 합성 자료에서도 명령어별 기계어와 제어 신호를 맞춰 해독 표시가 다른 명령어를 설명하지 않게 합니다.

실제 화면은 `/pipeline?example=addition`에서 컴파일 후 Single 모드의 데이터패스로 확인합니다. 정적 회귀 화면은 `/tests/browser/line-flow.html`입니다.

비트 해독과 명령어 의미의 근거: [RISC-V RV32I 공식 명세](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html).
