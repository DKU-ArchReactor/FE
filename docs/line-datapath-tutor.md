# C·ASM 줄별 싱글 데이터 흐름

이 변경은 선택한 C·ASM 명령어의 싱글 데이터패스 시각화에 한정합니다. 튜터 설명과 페이지 UI는 작업 전 develop 버전을 사용합니다.

싱글 데이터패스의 **명령어 흐름**은 CU, 레지스터, ALU, 메모리와 다음 PC 사이의 경로를 표시합니다. **전체 상태**를 선택하면 기존 데이터패스 화면으로 돌아갑니다. 파이프라인 시각화에는 이 싱글 경로를 적용하지 않습니다.

명령어 흐름 패널은 현재 명령어·클록과 간단한 재생 조작만 남기고 그림이 나머지 공간을 채웁니다. C 설명·처리 순서 카드·값 목록·제어 신호의 별도 설명은 이 패널에 중복해서 쌓지 않습니다. 장치 내부에서 실제 값을 확인하고, 자세한 설명은 튜터에서 봅니다.

그림 전체가 스크롤 없이 패널에 맞춰 표시됩니다. 기존의 PC → Instruction Memory → 레지스터·즉치값 생성 → 입력 MUX → ALU → Data Memory → 기록값 MUX 순서로 내려가는 세로 배치를 사용합니다. 레지스터는 녹색, ALU는 주황색, 메모리는 파란색, CU는 보라색으로 구분합니다. 메모리 연결에서 주소는 주황색, 데이터는 파란색, 제어는 보라색으로 강조하고 CPU 내부 경로와 구분합니다. CORE 로그에서 실제 버스 중재나 물리 배선 구조를 확인한 것은 아니므로, 버스 역할을 설명하는 개념도로 표시합니다.

현재 전송의 출발지·도착지·값을 그림 상단에 크게 표시합니다. 예를 들어 레지스터에서 ALU로 넘어가는 입력 A는 `11 · 0x0000000B`로 강조됩니다. 주소와 명령어 기계어는 의미 없는 부호 있는 십진수로 변환하지 않고 16진수로 표시합니다. 입력 도착·연산·레지스터 기록을 구분해 목적지 값을 순서대로 드러냅니다. 선과 이동점은 글씨보다 먼저 그리므로 글씨를 가리지 않습니다.

이동 경로에는 실제 값이 담긴 데이터 캡슐도 표시합니다. 도형과 겹칠 때 값을 숨기지 않고 가까운 빈 공간에 표시하며, 실제 경로상의 위치와 가는 선으로 연결합니다. Imm Gen·입력 MUX 근처의 짧은 경로는 값 표시 위치를 고정해 중간에 반대편으로 튀지 않게 하고, 이동점과 글자는 첫 프레임부터 함께 표시합니다. MUX 내부를 통과하거나 메모리 옆을 지날 때도 값을 확인할 수 있습니다. 큰 32비트 값도 말줄임 없이 표시합니다. 캡슐과 진행률은 같은 시계를 사용하므로 Pause/Resume 동작이 일치합니다.

주소·데이터는 선 색상과 같은 단색 표식에 실제 값을 표시해 이동합니다. 기본 1배속에서 일반 이동은 약 1.3~2.2초로 제한해 긴 반환 경로가 지나치게 느려지지 않게 합니다. 입력 MUX의 앞뒤, 기록값 MUX의 앞뒤는 각각 구분하며, MUX에 도착한 시점에는 ALU 입력 또는 레지스터 기록 완료로 표시하지 않습니다. 전체 싱글 클록 간격도 이 이동 시간의 합으로 계산합니다. 시간은 학습용이며 실제 회로 지연을 의미하지 않습니다.

진행 중인 선과 출발·도착 장치는 진한 색과 배경색으로 강조하고 나머지 배선·장치는 옅게 표시합니다. 장치명은 22, 내부 값은 18, 출발·도착은 16, 레지스터 비트 수는 15 SVG 단위의 굵은 글씨로 표시합니다. 설명은 기존 로컬 Pretendard 글꼴을 재사용하고 기계어·이동 값은 고정폭 글꼴을 사용합니다. CU 제어 신호는 보라색 점선 테두리와 `Read x…` 등으로 구분해 전달을 보여줍니다. 연산값이나 실제 전압 파형을 뜻하지 않습니다. 읽기 선택 신호와 레지스터 번호는 장치 위에도 계속 표시합니다. **Address Bus / Data Bus / Control Bus** 범례는 레지스터와 읽기 선택 표시에서 간격을 두도록 위로 올려 배치합니다. `명령어 주소 (PC)`는 PC에서 명령어 메모리로 전달하는 주소의 역할을 설명하는 라벨입니다.

Instruction Memory에서 Imm Gen으로 들어오는 명령어 비트 연결을 표시합니다. 즉치값을 사용하는 명령어와 조건 분기에서는 비트 전달·즉치값 구성 단계도 재생합니다. 레지스터 연산처럼 즉치값을 사용하지 않는 경우 이 연결은 비활성 상태이고 Imm Gen은 사용하지 않는다고 표시합니다. 이 연결은 명령어의 필드에서 즉치값을 구성하는 내부 경로이며 별도 메모리 읽기를 뜻하지 않습니다. [RISC-V RV32I 명령어 포맷과 즉치값 구성](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html#_immediate_encoding_variants)을 기준으로 설명합니다.

경로 좌표와 길이, 시간 배분은 명령어나 화면 크기가 바뀔 때 계산해 재사용합니다. 애니메이션 프레임에서는 미리 계산한 구간에서 이동 위치만 구합니다. 화면 크기를 바꾸어도 보고 있던 전송 단계와 재생·일시정지 상태를 유지합니다.

넓은 패널에서는 도형과 배선의 가로 배치를 넓혀 좌우 여백을 줄입니다. 글자의 가로 비율은 바꾸지 않으며 스크롤을 만들지 않습니다. 레지스터는 저장 행과 겹친 외곽선이 있는 32비트 뱅크 형태로, 메모리와 CU는 외부 핀이 있는 칩 형태로 표시합니다. 레지스터 행은 현재 명령어에 관련된 입력·기록 일부이며 전체 32개 레지스터를 모두 나열한 것은 아닙니다.

## 실행값 읽기

- 선택한 명령어의 PC와 현재 실행 프레임의 PC가 같을 때만 그 프레임의 실제 값을 표시합니다.
- 다른 명령어를 선택하면 의미를 먼저 보여줍니다. **이 명령어의 실행 시점으로 이동**을 눌러 관찰된 실행값을 확인합니다. 미래 클록의 값을 현재 값으로 가져오지 않습니다.
- CORE가 제공하지 않은 값은 `미제공`으로 표시합니다. 오류가 발생한 메모리 값이나 완료가 확인되지 않은 기록값은 숨깁니다.
- Store는 메모리 기록 경로를, Load는 메모리에서 목적지로 가는 경로를 표시합니다. x0 쓰기는 일반 레지스터 기록으로 그리지 않습니다.
- 싱글의 재생 배속은 대기 시간과 이동 시간에 동일하게 적용합니다. 파이프라인의 기존 클록 간격은 유지합니다.
- 전체 Pause 후 Play는 현재 이동점과 클록 타이머의 남은 시간부터 이어집니다. 그림 안의 Pause 후 재생도 같은 위치에서 이어집니다. 그림 안에서 직접 탐색·재생하면 전체 클록 재생을 멈추고 현재 클록만 봅니다. 이 상태에서 전체 Play를 누르면 현재 명령어의 흐름부터 다시 시작해 클록 타이머를 맞춥니다. 초기 상태와 Reset에서는 자동으로 흐름을 재생하지 않습니다.
- 전체 재생이 멈춰 있는 동안 스텝으로 클록을 바꿔도 그림은 일시정지를 유지합니다. 해당 클록의 흐름만 보고 싶으면 그림 안의 재생 버튼을 누릅니다. 클록 경계에서 Pause와 프레임 교체가 겹쳐도 애니메이션이 다시 시작되지 않도록 같은 규칙을 적용합니다.
- SVG 자체 타이머 대신 하나의 React 애니메이션 시계가 진행률과 경로상의 좌표를 계산합니다. 한 클록 안의 동작을 학습용으로 나누어 보여주며, 각 전송의 표시 시간이 실제 하드웨어 지연이나 추가 클록을 뜻하지 않습니다.

## 검증

`npm test`, `npm run build`, `npm run test:browser`를 실행합니다. 줄별 흐름 테스트는 값·클록 일치, Store와 x0 Load, 오류, 시프트, 점프, 실제 이동 좌표, 전체/지역 Pause·Resume, 스크롤 없는 반응형 배치와 글씨 경계를 확인합니다. `?geometry=`로 실행하는 표시는 큰 값과 명령어별 배치를 검사하는 합성 UI 자료이며 CORE 실행의 정확성을 검증하는 자료와 구분합니다.

`tests/browser/fixtures/line-flow.json`은 실제 BE/CORE에서 실행한 `11 + 7` 예제의 연속된 `lw → lw → add → sw` 네 프레임과 직전 상태를 담은 회귀 자료입니다. 전체 프로그램의 실행 이력은 아닙니다. 매핑에서 중복된 목록을 덜어냈으며, 기존 튜터 메타데이터만 사용합니다. 인증 토큰은 포함하지 않습니다. 정적 브라우저 검증 화면은 `tests/browser/line-flow.html`이고, 실제 컴파일·실행 확인은 `/pipeline?example=addition`에서 합니다.
